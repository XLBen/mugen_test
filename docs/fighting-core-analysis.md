# 通用 2D 格斗游戏底座（白模）—— 系统级拆解与取舍

## 目标
把《街头霸王》《罪恶装备》《拳皇》拆到"子系统 + 数据字段"粒度，找出共通抽象，
据此为 `mugenlike`（Godot 4.7）设计一个可扩展、数据驱动、白模（色块+判定框）的格斗底座。

## 已定方向
- 第一套参考规则：**街霸风**（GG / KOF 作为后续规则模块）
- 逻辑语言：**GDScript**
- Rollback：**预留不实现**（第一版就保证确定性 + 存读档）

## 一句话结论
三作的核心循环（固定 60 帧 → 输入 → 状态机 → 判定盒 → 命中结算 → 表现）完全一致，应固化为底座；
差异集中在 **移动选项 / 取消规则 / 资源系统 / 连段限制 / 防御体系 / 比赛模式**，做成可替换的规则模块。

> 文中具体数值是记忆中的参考值，用于说明量级与机制形态；真正调参前请对照
> SuperCombo / Dustloop / Dream Cancel wiki 的帧数据核实。

# A. 子系统拆解（三作做法 → 共通抽象 → 底座设计）

## A1. 时间与帧
- **三作**：逻辑固定 60fps；一切数据以帧计。另有三种"时间扭曲"：
  - Hitstop（顿帧）：命中/防御时双方冻结若干帧，强度越大越久（SF 轻攻击约 10 帧级别，重攻击更久）。
  - Superfreeze（超必杀暂停）：放超杀时对手与飞行道具冻结，释放者继续走启动帧。
  - 慢动作：GG 的 Roman Cancel 让对手减速；GG Strive 的大打康也有慢放。
- **共通抽象**：全局帧计数 + **每个实体自己的冻结计数器 & 时间缩放**。
- **底座设计**：`Entity.freeze_frames`、`Entity.time_scale`（整数分数，如 1/2 表示隔帧推进），
  仿真 step 时跳过冻结中的实体。超杀暂停 = 给除释放者外所有实体加冻结。

## A2. 输入系统
- **方向**：小键盘记法 1–9，5 为中立；**按"当前朝向"解释前/后**。
- **按键**：SF 6 键（LP/MP/HP/LK/MK/HK）、GG 5 键（P/K/S/HS/D）、KOF 4 键（A/B/C/D）。
  SF6 另有 Modern 操作（一键必杀）→ 说明"物理输入 → 指令"之间需要一层可替换映射。
- **指令种类**：
  - 搓招：236 / 214 / 623 / 41236 / 63214
  - 蓄力：后蓄 → 前+键（[4]6P），下蓄 → 上+键（[2]8K），需持续若干十帧（约 40~60 帧量级）
  - 回旋：360 / 720（SF 桑吉尔夫、KOF 克拉克、GG 波将金 632146）
  - 双击：66 冲刺 / 44 后撤
  - 同时按：投（SF LP+LK）、KOF AB 翻滚 / CD 吹飞、SF6 MP+MK 斗气格挡，同时判定窗口 1~3 帧
  - 按住/松开：SF 系的 Negative Edge（松键也算按下）、GG 的蓄力键技
- **宽容度**：每段方向之间允许的最大间隔、捷径（623 可用 6236 / 3236 完成）、
  输入缓冲（指令完成后若干帧内仍有效，用于取消/起身/落地等"一帧窗口"）。
- **优先级**：同一帧多个指令都成立时，超杀 > 必杀 > 特殊技 > 普攻；623 优先于 236。
- **共通抽象**：输入历史环形缓冲 + 声明式指令模式 + 优先级排序。
- **底座设计**：
  - 存"绝对方向"（左/右），匹配时按"当前朝向"翻转（可选按"输入那一帧的朝向"翻，处理越身搓招）。
  - `MotionDef`：步骤序列（方向集合 + 最大间隔帧）、按键条件（按下/松开/按住 N 帧）、缓冲帧、优先级。
  - 蓄力用独立计数器（按住 4 方向的连续帧数，允许"蓄力分割"的宽容）。
  - 逻辑按键用抽象槽位 `B0..B5`，规则模块声明用几个；物理键 → 槽位映射独立。

## A3. 移动
| 选项 | SF | GG | KOF |
|---|---|---|---|
| 走 | 有，前后速度不同 | 有 | 有 |
| 冲刺 | 固定距离步冲 | 按住跑 / 步冲（角色区分） | 按住跑 |
| 后撤 | 有，部分无敌 | 有，前段无敌 | 有 |
| 跳 | 固定轨迹，前跳 / 垂直 / 后跳 | 二段跳、高跳、空冲 | 小跳 / 中跳 / 大跳 / 小大跳（4 种高度） |
| 回避 | — | — | 翻滚（AB，全身无敌但可被投） |

- **共通**：起跳前有 3~4 帧的预备帧（期间可被投、算地面）；空中轨迹一经确定不可改（除空冲/二段跳）；
  落地有落地硬直；**自动转向只在中立/可行动状态发生**，空中不转。
- **底座设计**：
  - 物理：整数位置/速度/重力/摩擦；`PhysicsMode = Stand / Crouch / Air / None`。
  - 移动选项是角色数据 + 规则开关：`air_actions = 1`（二段跳/空冲共用次数）、`jump_types[]`、`dash_type = step|run`。
  - 推挤盒（Pushbox）：地面与空中两套；两人重叠时按重叠量对称推开；**到版边时推力全部转给另一方**。

## A4. 状态机
- **三作**：本质一致——"站/蹲/空中/倒地" × "中立/攻击/受击/防御"。MUGEN 把它显式化为
  `StateDef`：`statetype (S/C/A/L)`、`movetype (I/A/H)`、`physics`、`ctrl`。
- **关键概念**：
  - `ctrl`（可行动）：只有 ctrl=true 才接受新指令（取消窗口是例外）。
  - **对手接管状态**：投技命中后，被投方进入"由攻击方提供"的状态（MUGEN 的 p2stateno），
    位置/动画由攻击方逐帧控制。
  - 公共状态（受击、防御、倒地、起身、被投）所有角色共用；招式状态角色私有。
- **底座设计**：`StateDef`（Resource）= 通用标志 + 帧时间轴（盒子、速度、事件、取消窗口）。
  公共状态放 `rules/common_states`，角色只写自己的招式；投技能指定"被投方状态脚本"。

## A5. 判定盒与命中检测
- **盒子种类**：Hurtbox（受击）、Hitbox（攻击）、Pushbox（碰撞体积）、Throwbox（投判定）、
  Throw-hurtbox（可被投的范围），以及 GG 的 "Clash" 判定（攻击盒对攻击盒相杀）。
- **关键细节**：
  - 出拳时**受击盒随手伸出**，所以存在"拆招/差し返し"（打对手伸出来的手）。
  - **每次攻击只命中一次**：同一攻击盒在其持续帧内命中后失效；多段技用"命中 ID"分段重置。
  - **相打（Trade）**：同帧双方都命中 → 都吃伤害（SF 典型）。
  - **投 vs 打、投 vs 投 的同帧优先级**因作而异 → 需要可配置的优先级表；投 vs 投 = 拆投。
  - **投不可**：受击/防御硬直中、硬直结束后若干帧、起身若干帧、跳跃预备之外的空中。
  - 飞行道具：有"耐久/命中数"，道具 vs 道具互相抵消（EX 波动耐久更高）。
- **底座设计**：
  - 只用 AABB；盒子按"帧区间"定义（不是每帧一份），朝向翻转在运行时做。
  - 每帧检测流程：**先收集所有碰撞对 → 按固定顺序统一结算**（避免 1P 优先），
    顺序：投 vs 投 → 投 vs 打 → 打 vs 打（含相杀）→ 道具 vs 道具 → 打 vs 受击。
  - `HitTracker`：记录"哪个攻击 ID 已经打中了哪个实体"。

## A6. 命中结算（HitDef）
每个攻击盒携带一份 `HitDef`，字段大致：

| 字段 | 说明 | 三作差异 |
|---|---|---|
| damage / chip_damage | 伤害 / 削血 | SF 只有必杀技削血；GG 有 FD 可免削 |
| hitstun / blockstun | 受击 / 防御硬直 | SF 逐招手调；**GG 用"攻击等级 0~4 查表"统一** |
| hitstop (atk/def) | 双方顿帧，可不同 | 打康时加长 |
| pushback (hit/block) | 击退距离 | 版边时反推攻击方 |
| guard_type | 上/中/下段、可空防否、不可防 | GG 地面普攻不能空防（需 FD） |
| hit_effect | 普通 / 浮空 / 击倒(软/硬) / 蹒跚 / 墙弹 / 地弹 / 旋转 | 打康可替换为别的效果 |
| juggle props | 能否追打、浮空计数消耗 | 见 A9 |
| meter gain (atk/def) | 双方涨气 | 见 A8 |
| guard_damage | 削防 | KOF 防御槽、SF6 Drive 削减、GG R.I.S.C. 增加 |
| counter overrides | 打康时的修改 | 见 A7 |
| proration | 本招对后续伤害的补正 | 见 A9 |

- **底座设计**：`HitDef` 支持两种写法——**等级查表**（GG 式，快速出白模）和**显式覆盖**（SF 式手调）。
  规则模块提供默认表，角色招式只写差异。

## A7. 打康（Counter Hit）
- **SF6**：
  - Counter（打中对手招式的发生/持续帧）：受击硬直约 +2 帧、伤害约 ×1.2。
  - Punish Counter（打中对手的收招硬直、或在对手行动中投中）：硬直约 +4 帧、额外削对手 Drive 槽，
    部分招式在 PC 时变成蹒跚/击倒/浮空 → 延伸连段。
- **GG**：打康大幅增加受击硬直与顿帧、空中被打康不可受身时间更长；
  Strive 区分小打康/大打康（大打康带慢动作，多为重攻击），很多招的连段路线就建立在打康上。
- **KOF**：传统上普遍打康收益较弱；部分招式有"打康时击倒/墙弹/可追打"的特殊属性（XIII / XV）。
- **共通抽象**：打康类型 = f(**被击中者当前招式所处阶段**)：
  - 中立 / 移动 → 普通命中
  - 发生 / 持续 → Counter
  - 收招 / 后撤后段等 → Punish Counter（规则模块可选开启）
  - 再由 HitDef 的 `counter_overrides[type]` 决定加成：硬直 +N、顿帧 +N、伤害倍率、
    效果替换、额外资源变化（涨气/扣对手槽）、是否显示 "COUNTER" 字样。
- **底座设计**：
  - 每个 StateDef 自动从帧时间轴推导阶段：首个攻击盒之前 = startup，攻击盒存在 = active，之后 = recovery；
    允许逐帧覆盖（如多段技中间的空档）和 `counterable=false` 标记。
  - 投技同理：被投时对手处于收招 → "投康"（SF6 加伤）。
  - 训练模式显示打康类型 + 是否连上，用于验证。

## A8. 能量 / 资源系统
| | SF6 | GG Strive | KOF XV |
|---|---|---|---|
| 主资源 | 超必杀槽（3 格） | Tension（100%） | 能量槽（多格，后出场队员格数更多） |
| 主资源获取 | 出必杀、命中、被防、被打（少） | 前进、命中、出招；后退 → Negative Penalty | 出招、命中、被防、被打 |
| 消耗 | Lv1/2/3 超杀、CA | 超杀、RC（50%）、FD（持续消耗） | 超杀、EX、MAX 发动 |
| 第二资源 | **Drive 槽（6 格）**：自然回复、前进/命中回复，防御与被斗气冲击削减；耗尽 → Burnout（不能用 Drive 系统、防御被削血） | **Burst 槽**：随时间与受伤涨；**R.I.S.C.**：防御时涨，满了下次被打大幅增伤 | **防御槽**：被防削减，归零 Guard Crush；MAX 模式计时条 |
| 状态 | Burnout | Negative Penalty / Positive Bonus | MAX 模式（持续时间内可做特殊取消） |

- **共通抽象**：所有作品都有 **2~3 种资源**，形态一致：
  `当前值 / 上限 / 分格(stock) / 回复规则 / 获取事件 / 消耗 / 冷却 / 阈值状态`。
- **底座设计**：通用 `Resource` 组件（命名为 `Gauge` 避免与 Godot Resource 冲突）：
  - `id, max, segments, value`
  - `regen_per_frame`、`regen_delay_after_use`（SF6 用完 Drive 后有回复停顿）
  - `gain_table[event] -> amount`：事件 = on_hit / on_blocked / on_whiff / on_get_hit / on_block /
    on_move_forward / on_special / on_parry ...（由规则模块定义）
  - `scaling`：连段中涨气递减（防止连段刷气）
  - `thresholds`：值为 0 进入 Burnout、满格进入 MAX 等，触发状态事件
  - 招式在 StateDef 里声明 `cost {gauge_id: amount}`，不够则指令不成立
- **取舍**：只写死一个"超杀槽"更快，但三作都至少需要两种资源；通用 Gauge 的成本很低，直接做。

## A9. 连招系统
**连接方式**（底座要能"自然涌现"它们，而不是逐个硬编码）：
1. **目押 / Link**：自己收招结束后对手仍在硬直 → 由帧数据自然决定，无需特殊代码。
2. **取消 / Cancel**：在指定帧窗口内（通常在命中/被防的顿帧里），直接转入另一招。
3. **连打取消 / Chain**：SF 轻攻击连打；**GG Gatling**：P→K→S→HS→D 的路线表。
4. **Target Combo**：特定顺序的专属组合（SF）。
5. **追打 / Juggle**：对手浮空时继续命中。
6. **OTG / 墙弹 / 地弹**：特殊效果后的延伸。
7. **资源取消**：GG Roman Cancel、SF6 Drive Rush 取消、KOF MAX 模式取消 / 超杀取消 / 极限取消。
8. **跳跃取消**（GG）、**Kara 取消**（SF，发生前取消）→ 也只是取消窗口的特例。

**取消窗口统一描述**：
```
CancelWindow { frames: [start, end], condition: hit|block|whiff|always,
               targets: [tag 或 move_id], cost?: {gauge: n} }
```
规则模块给出默认路由（"normal 可取消到 special"、"special 可取消到 super"），角色只写例外。
取消窗口大多落在顿帧内 → 必须配合输入缓冲。

**连段限制（防无限）**：
| 机制 | SF | GG | KOF |
|---|---|---|---|
| 伤害补正 | 第 3 击起递减（约 80%→70%→…，有下限）；起手招与 Drive Rush 额外补正；超杀有最低保底 | 每招自带 proration（初始补正 / 强制补正）+ 根据剩余血量的 Guts | 击数递减 |
| 浮空限制 | Juggle 点数：每招有"起始值 / 上限 / 增量"，计数超过上限就打不中浮空对手 | 重力随连段时间增大 + 受身不能时间随连段时间衰减 | 只有标记"可追打"的招能打浮空 + 追打计数 |
| 其他 | 版边推开 | 同招重复限制、撞墙(Wall Break) | 防御槽 / MAX 时间 |

- **底座设计**：一个 `ComboState`（挂在被打者身上）：`hit_count, combo_frames, juggle_points,
  proration, gravity_scale, hitstun_decay, used_moves`；**由规则模块的 `ComboRules` 读取并修改 HitDef**。
  三作的限制方式都能用"读 ComboState → 改伤害/硬直/重力/能否命中"表达。
- **受身**：空中受身（硬直结束后可按键）、地面受身（快速起身/后滚起身）、硬击倒（不可受身）。
- **连段判定 / 计数**：被打者在两次命中间是否恢复过 ctrl → 决定 combo 是否中断（训练模式显示"真连"）。
- **逃脱手段**：GG Burst（受击中可用）、SF6 Drive Reversal（防御中）、KOF 防御取消 → 规则模块提供的"特殊防御行动"。

## A10. 防御体系
- **普通防御**：按后 = 防御；**近距离防御（Proximity Guard）**：对手攻击在附近时按后会进入防御姿态而不是后退走。
- **上中下段**：站防挡上/中段，蹲防挡下段；中段(Overhead) 必须站防。越身（Cross-up）按命中瞬间相对位置决定防御方向。
- **空防**：GG 有、SF 无。
- **进阶防御**：
  - GG：Instant Block（精准时机，减防御硬直、涨气）、Faultless Defense（耗气，加大推开、免削血）
  - SF6：Drive Parry（按住，耗 Drive 槽，精准时机 = Perfect Parry）；SF3：Blocking
  - KOF：防御取消翻滚 / 吹飞（耗气）
- **破防**：KOF Guard Crush、SF6 Burnout 时在版边被斗气冲击 → 晕眩、GG R.I.S.C. 满 → 下次被打增伤
- **投与拆投**：投判定范围、拆投窗口（数帧）、拆投后双方推开；指令投不可拆。
- **底座设计**：`GuardRules` 规则模块：防御条件（方向 + 状态 + 段位）、可选进阶防御行动（作为特殊 StateDef + 资源消耗）。

## A11. 倒地、起身与压起身（Okizeme）
- 击倒类型：软击倒（可快起）/ 硬击倒（固定倒地时间）/ 特殊（墙弹、地弹后倒地）。
- 起身时间**确定**（这是压起身战术成立的前提）；起身有无敌帧。
- **Reversal**：起身最后几帧输入的招会被缓冲并在第一可行动帧发动（升龙无敌）。
- **Meaty**：用攻击的后段持续帧命中起身者 → 有利帧更多（硬直从命中帧开始算，**会自然涌现**，前提是硬直计算正确）。
- **底座设计**：倒地/起身是公共状态；起身无敌与投无敌用帧标记；输入缓冲覆盖"最后 N 帧"。

## A12. 摄像机与舞台
- 摄像机跟随两人中点，垂直方向有限跟随；KOF 会缩放。
- **两人间距最多一屏宽**：屏幕边缘是"动态墙"，与舞台边界（版边）是两回事——这一点三作一致且非常关键。
- 版边（Corner）：推挤反作用到攻击方。GG Strive 版边可以撞墙(Wall Break) 换场。
- **底座设计**：逻辑层计算"摄像机边界"（作为确定性状态的一部分，因为它影响碰撞），表现层只负责平滑显示。

## A13. 实体（飞行道具 / 召唤物 / 特效）
- 飞行道具：SF 波动、GG 召唤物（Zato 的 Eddie）、设置物（Venom 的球）。
- 关键属性：拥有者、耐久、同屏数量上限、拥有者被打时是否消失、是否受超杀暂停影响。
- **底座设计**：所有实体共享 `Entity` 基类（位置/状态/盒子/冻结），角色只是"带输入的实体"。
  纯视觉特效（火花、残影）不进逻辑层。

## A14. 体力与比赛结构
- 体力：SF6 大多 10000；GG 有角色防御系数 + Guts；KOF 的 3v3 后续队员会回复部分体力、能量格增加。
- 可恢复伤害（白血/灰血）：被防削血或特定系统中出现，一段时间不被打会回复。
- 计时（99 秒，每秒按固定帧数计）、时间到按剩余血量判定、双 KO、回合数。
- **底座设计**：`MatchRules`（回合制 / 3v3 车轮 / 以后 Tag）可替换；回合之间的数值继承由它决定。

## A15. 调试与训练工具（白模阶段的核心生产力）
- 判定框显示（hurt/hit/push/throw 不同颜色）
- **帧计量条**（SF6 / Strive 风：每帧显示 发生/持续/收招/硬直，自动算有利帧）
- 输入历史显示、指令识别结果显示
- 假人设置：站/蹲/跳/自动防御/录制回放/受身
- 状态重置、单帧步进、慢放
- 确定性校验：逐帧状态哈希

## A16. Rollback 的前置约束（预留不实现）
- 逻辑层所有状态可序列化（`save_state() -> Dictionary`、`load_state()`），且重演 8 帧以内足够快。
- 不读系统时间；随机数用种子化 RNG 并纳入状态（GG Faust 的随机道具这类）。
- 逻辑层只用整数；音效/特效触发要能"回滚后不重复播放"（按帧号 + 事件 ID 去重）。

# B. 关键取舍（建议）

1. **逻辑与表现彻底分离**：逻辑是纯 GDScript 对象，不用 Godot 物理 / Area2D / AnimationPlayer 驱动逻辑；
   表现层每帧读状态绘制。代价：失去部分节点便利；收益：确定性、回滚、无头测试、录像回放。
2. **整数坐标**（1 像素 = 100 单位），避免浮点不一致。
3. **数据驱动 + 脚本钩子**：通用部分全部 Resource 数据；特殊机制允许 `on_frame / on_hit / on_hurt` 钩子。
   纯数据（MUGEN 式）表达力有天花板，纯代码难做工具，混合最平衡。
4. **固化核心循环，差异做成规则模块**：五个扩展点——
   `MovementRules / CancelRules / GaugeRules / ComboRules / GuardRules`（+ `MatchRules`）。
   先只实现 SF 风一套，**不要预先实现所有作品的所有选项**。
5. **HitDef 双模式**：等级查表（快）+ 显式覆盖（精）。
6. **盒子按帧区间定义**，只支持 AABB。
7. **逻辑帧驱动显示**，而不是动画驱动逻辑。
8. **统一结算顺序**：先收集再结算，P1/P2 对称。
9. **训练工具与底座同时做**：没有帧计量条和判定显示，白模无法调。
10. **工具链分期**：第一期用 `.tres` 手写数据 + 运行时可视化；判定框编辑器插件放第二期。
